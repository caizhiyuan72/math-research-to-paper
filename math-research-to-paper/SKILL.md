# 数学科研：从选题到论文

把科研作为一系列有证据的可审查步骤，而不是为了产出论文而强行制造结论。默认中文交流；论文语言、目标期刊、作者署名及交付范围遵循用户要求。未指定时用中文研究稿、规范 LaTeX 与英文题目/摘要（如需要）；不得擅自填作者、单位、经费或投稿信息。允许适配其他数学分支。

## 1. 确定入口与研究状态

- “根据这个 Skill 写一篇论文”“继续”或“完善这篇论文”承接完整的研究、写作、审查与修订任务。恢复当前证据，找出最影响交付的未决问题，在本轮实际推导、试验、查原文或编辑稿件。只在用户明确要求“只审稿”“只提意见”时交付单独报告。
- 从已有对话、用户给出的论文、源码、数据与研究交接材料恢复研究状态。先核实最新版本，保留原稿，不重复已经确认的工作。读取实际文件，不凭过去的总结认定证明成立。
- 若是新课题，明确研究对象、基础知识、文献边界与目标；若已有稿件，先建立待审查的主张清单；若已有审稿意见，直接进入逐项修订。
- 在当前轮完成尽可能多的实质工作；复杂研究给出简短方案，并在阶段结束时汇报可核验结果。没有得到证明时停在真实的进展处，不许承诺后台工作或保证突破。
- 使用 `references/research-method.md` 规划文献、实验、证明和反例工作；使用 `references/manuscript-review.md` 规划写作、审稿和修订。需要选题或拟产出正式论文时，先读 `references/quality-gates.md`，按当前阶段执行选题、开写和交付检查。
- 对多轮项目建立持久的研究目录及主张台账。以 `assets/claims.json` 为模板，复制 `assets/research-handoff.md` 并随迭代填写。文件路径由实际环境确定，严禁提供未生成文件的链接。

## 2. 文献筛选与研究切入点

1. 针对当前问题检索 arXiv、期刊原文、作者公开版本以及相关引用文献；涉及最新论文时确认日期与版本。只有摘要可读时明确限制；不能把摘要阅读说成通读正文。
2. 摘录研究对象、假设、主要定理、证明方法、开放问题以及适用边界，附真实出处（文献题名、作者、年份、DOI/arXiv ID、定理编号或页码）。禁止编造参考文献、未读结论或搜索结果。
3. 区分作者明确提出的开放问题、由已知定理立即推出的结果、可能的新问题。检查已知一般理论是否已覆盖拟研究的特例。给出具体可操作的候选方向，比较难度、数学价值、可验证性和已有工作的重合程度。
4. 用户让“试试”“继续推进”时，选择有依据且可攻克的子问题，实际推导和测试，而非只提供计划。记录选择理由。优先寻找可统一解释的结构；若遇到反例，修改猜想，不隐藏失败。

**选题条件。** 立项前把候选写成精确的数学问题，核实它与最近原始定理的差别，对优先候选实际试推关键引理或找反例，再判断一个可望拿到的结果是否有足够价值。记录淘汰理由和首个可验证的目标，运行 `check_release.py topic`。未通过的仍可作为试探方向；用户已经给定的问题直接做同样的评估。

## 3. 实验、猜想与证明循环

- 先给出精确定义、量词、变量范围、规范化及退化情形。写出小例子手算；选择恰当的精确整数/有理数、符号计算或可复现枚举方法，避免浮点近似冒充严格数学证据。
- 尝试原始直接算法与结构算法相互验证；搜索反例、极端参数、最小规模、不同特征/维数等相关边界。只报告真实执行得到的参数范围、统计数、运行结果和失败情况，保存命令、代码、日志。不能执行时标为未运行。
- 从现象提取猜想，优先建立引理、标准形、双射、递推、分解、有限状态、生成函数或不变量等一般机制。每条化简规则证明合法性、终止性；另行证明完备性、唯一性或精确扣重，不能将终止性等同于合流性。
- 对每个核心结论给出从假设到结论的完整推导，包括充分/必要方向、边界、变量范围与外部定理的适用条件。凡从有限检验推广到无限参数，必须有独立的有限归约、归纳或完备性定理。计算机辅助证明可以严格成立，但必须给出可检查的证书和穷举完备性论证。
- 对推导出的结论主动换方法检查，例如把公式与直接枚举对比，尝试证伪，核查代数次数、分母、端点和低阶例子。不要使用同一套实现的重复运行冒充独立复现。
- 每轮更新主张台账：`conjecture`（猜想）、`finite-evidence`（有限证据）、`derived-unchecked`（推导待核验）、`proved`（有一般性证明）、`computer-assisted`（有严格归约及计算证书）、`refuted`（已否定）。另记原创性与外部依赖；`proved` 不等于已获人类同行认可。
- 只有在证据相应完备时使用“证明”“解决”“最小”“对所有”等强措辞。绝不虚构测试次数、定理、独立核验、人类审稿或首创性。遇到实质证明漏洞，撤销受影响主张，标明依赖并重新推导。

## 4. 科研收束与初稿

- **开写条件。** 写正式初稿前，先实际攻克一个决定研究深度的数学障碍，再核对贡献、主定理的证明链、边界检验和最接近的已有结果。记录本轮推导及实际证据文件，运行 `check_release.py draft`。任一项未通过，先尝试修补，再按所得证据决定是否成文；可以先做纲要、证明草稿或审查已有稿件。
- 按逻辑而非研究时间线组织：问题与背景 → 定义/预备知识 → 主定理 → 分解的引理与证明 → 推论与例子 → 局限及开放问题。重要结论尽早陈述；先解释为什么引入符号，再给公式。证明必须让读者可逐步核查。
- 输出正式数学论文，不使用“第几轮研究”“V1.5版”等历史痕迹；默认中文行文统一用“本文”，证明中可自然使用“我们”。规范定理、引理、命题、推论、交叉引用、参考文献和 MSC 分类（需核实）。不夸大结果或堆砌抽象术语。研究日志、审稿回复与 AI 辅助说明单独保留；论文中的 AI 披露依据实际使用及目标期刊规范。
- 使用 `assets/manuscript-template.tex` 作为可选起点，遵守对应 PDF/DOCX 工具的要求。实际编译、检查引用与溢出、渲染全部页面并检查公式、表格、分页和手机端可读性；若缺少编译器或其他依赖则交付可用源码并明示未生成 PDF。
- 提供 PDF、LaTeX/BibTeX、必要的代码和可复现证书、README 及研究交接资料。用户仅需阶段性研究或审稿报告时，不强制生成整篇论文。

## 5. 模拟审稿与大修闭环

- 用户请求审稿时先读取当前实际稿件、补遗与可用代码，再以严格的独立审稿视角检查；不要受自己先前的评价影响。使用 `references/manuscript-review.md` 的审稿流程。
- 正式论文交付前，对照实际稿件分别审查证明、计算证据、文献与贡献、全稿与交付物。首次审查完成后，另做验收复核，检查修复后的证明链与受影响的正文。给问题分配固定编号，整改后以可复核证据关闭；仍有待核验项时停止正式交付。
- 按问题严重性列出具体章节、公式、定理和可复现反例，说明对结论的影响、要求如何修改。给出模拟决定（拒稿/大修/小修/可接受），明确并非真实期刊审稿。没有必要默认打分；若评估 SCI 期刊，区分期刊分区、稿件质量和录用可能性，查明时间及分区口径，不保证录用。
- 生产或完善论文时，发现实质问题立即进入修订。先修主定理、依赖和原创性判断，再做文字与版式。能补的证明本轮补上；结论被推翻或目前证据只支持较窄范围时，实际修改主张与受影响章节，并将原目标保留为未解决。只有 PDF 时，将可独立复核的替换段落、证明或重算表写成修订稿。复核发现新问题时回到修订，继续检查受影响的内容。
- 在二轮及后续审稿中对新增内容进行重点审查，同时复核原问题是否真正关闭。保持逐条回复文档（参见 `assets/review-response.md`）；注明改动位置、证据与仍未完成项。

## 6. 投稿前检查与交付

- 复核核心定理及全部依赖、实验可复现性、引用准确性、原创性边界、反例与最小性主张、作者信息和学术规范。对关键外部定理尽可能读原文并核对假设；无法获得全文则标注依赖风险。
- **交付条件。** 验收复核覆盖当前版本的全部审查项，审稿问题已逐条关闭，并且 `check_release.py final` 对当前材料检查通过，才可称为正式定稿。脚本检查台账依赖、审查记录及版本一致性；实际数学论证由审查者核查。遇到无法解决的缺口时交付阶段结果及待解决问题。
- 通过后打包最终论文、源码、代码、数据/证书、执行说明、依赖版本、日志、最新审稿回复及 handoff。核实压缩包路径与文件存在，不将旧稿当新版。
- 输出已完成成果、证明方式、实际运行范围及剩余风险。未经作者独立核验，不宣称达到可发表标准；未经明确许可，不代用户投稿、公开仓库或上传未发表研究。

## 阶段入口示例

| 用户要求 | 直接执行 |
|---|---|
| “找近期代数论文，挖掘新方向” | 对照原始定理筛候选，试推优先候选，再决定推荐或保留观察 |
| “继续深入这个猜想” | 恢复台账，尝试证明/反证与实际计算 |
| “继续”且已有初稿或审稿意见 | 实际攻克最重要的未决项并写入修订稿，重核相关证明与主张 |
| “还需要深入吗” | 对照核心定理、原创性与证据缺口，提出收束建议 |
| “写一份初稿” | 先检查开写条件；通过后用已证结果写作并实际编译检查 |
| “你作为审稿人审稿” | 审核实际稿件和证据，提出可操作审稿意见 |
| “按要求继续完善” | 逐条关闭审稿意见，实际修改并重新核验交付 |
