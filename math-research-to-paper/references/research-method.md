# 研究方法与证据规范

## 文献记录

为每个相关来源记录：准确题名、作者、年份、期刊/预印本版本、DOI 或 arXiv 链接、实际阅读范围、有关定理编号/假设、与本项目的关系（直接已有、特例、扩展、未知）。如研究 arXiv 某日更新量，区分首次投稿、交叉列表、修订稿和去重结果；不要用搜索引擎条目数代替官方统计。对最近的预印本结论尤其注意版本和是否已发表。若已有一般定理推出新发现的公式，将其表述为应用/推论，解释真正增量。

## 形成可检验的研究问题

先写明输入对象的标准化、目标不变量、参数的取值与量词。通常优先固定一个参数、研究最小反例、证明一个结构性引理、寻找对称性或不变量的等价关系。实验数据可以引导猜想，不是证明。候选研究方向的选择依据：数学意义、已知工具、可证伪性、与文献差距、当前资源。若难以证明全分类，尝试给充分条件、无限构造、显式反例、局部定理或严格上下界，并保留未解决部分。

## 计算证据与完备性

- 记录实验目标、算法伪代码、输入生成方式、规范化及去重理由、范围、代码版本、命令、软件依赖、随机种子（若使用）、真实输出、错误与耗时（若记录）。用独立小实例手算确认定义。
- 尽量使用标准库精确数值、整数位集、任意精度整数、符号代数或形式证明系统；若存在溢出或截断，证明范围足够。保存最小可重现实例。
- 独立核验改变核心实现思路（如直接枚举对照结构计数、动态规划对照最短路），而非仅换语言、重跑同一算法。检查负例和边界。测试范围要明确，统计次数从实际日志提取，不能估计后冒充实测。
- 有限分类定理的搜索必须覆盖全部候选，并证明剪枝不漏解、去重保持目标性质、每个被排除对象有确定判据。用已知小范围计数或独立算法核查总数。只验证几个样例不能证明最小性。
- 无限参数定理必须有一般性论证，或将无限情形严格归约为有限证书。对固定参数验证无限层级时，也必须证明稳定性/有限判据；不能以此推出所有参数成立。清晰区分两层量词。
- 计算证书至少包含源代码、输入范围、运行方法、输出及人工可审查的正确性证明；有条件时提供第二实现或可独立验证的证书。若使用 Lean 等形式系统，实际编译并记录版本、未闭合的目标与 `sorry`；否则只称形式化草稿。

## 证明核查清单

1. 定义一致吗？是否漏掉空集、零参数、极小参数、非互素、非标准化、特征变化等适用情形？
2. 引理究竟证明了哪个方向？存在性、唯一性、完备性、最小性是否各自成立？
3. 每一步改写是否保持研究对象及其权重/次数？计数是否覆盖全部情况，是否重复？标准形数量相同并不自动意味着标准形唯一；终止不意味着合流。
4. 若用生成函数、差分或极限，分母、初始项、边界截断及系数符号是否正确？
5. 若用外部定理，原文的领域、假设、编号、版本及结论是否完全匹配？是否误把推论当原定理？
6. 是否存在循环论证、跳步、未说明的排序、对称变换、非相邻交叠、消去、反射与平移混淆？
7. 有无独立的低阶例子、边界测试或反例搜索？数值一致仅增强信心。
8. 证明所需的每个依赖是否已经证明或可靠引用？若否，将主张标记为待核验，并检查摘要、结论与下游结论。

## 主张状态和原创性

主张台账的 `status` 仅表明当前数学证据：conjecture / finite-evidence / derived-unchecked / proved / computer-assisted / refuted。`novelty` 独立标记 unknown / known / consequence / candidate-new。`candidate-new` 表示经有记录的针对性检索暂未发现相同结果，不是首创认证。将文献依赖和证据路径记录到相应字段。若真实证明尚未核验，避免在交接材料中将它升级。稿件中可按通常数学写作将完成证明的主张表述为定理，但应明确未核验或有缺口的主张不应作为已证定理。台账检查脚本不会检查证明内容。

## 持续推进与停止条件

每轮回答：解决了什么、为什么成立、验证范围是什么、哪些尚未证明、下一步最值得攻克哪一点。若用户让继续深入，在同轮实际工作并输出有效结果；若尝试失败，写明障碍及已排除的方向。优先完成支撑主定理的必要条件；边缘的完整分类、纯理论替代计算证书等不必无止境扩展。以数学正确性和清晰贡献为收束标准，不以页数或分区为目标。

## 台账字段示例

每条记录使用 `id`、`statement`（完整主张）、`scope`（量词和验证范围）、`status`、`novelty`，以及按实际情况填写的字符串数组：`proof_files`、`code_files`、`log_files`、`commands`、`sources`（引用或检索记录）、`dependencies`（本台账其他主张 ID）。证据文件路径相对研究根目录。可增加备注和待解决事项。初始空模板不会假装存在结论；填充后再检查。`proved` 必须关联证明文件；`computer-assisted` 同时需要归约证明、代码、日志和命令；`finite-evidence` 需要代码、日志和命令。若环境不支持实际计算，保留为猜想或推导待核验，不填假日志。

例：
```json
{
  "id": "C1",
  "statement": "某类对象的计数可能满足一个固定递推关系（填写精确表达式）",
  "scope": "待确定一般参数范围",
  "status": "conjecture",
  "novelty": "unknown",
  "proof_files": [],
  "code_files": [],
  "log_files": [],
  "commands": [],
  "sources": [],
  "dependencies": []
}
```
