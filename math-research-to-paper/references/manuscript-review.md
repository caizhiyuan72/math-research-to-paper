# 正式论文写作、审稿与修订规范

## 论文结构

默认采用研究型数学文章的结构，按课题调整：题名；摘要（问题、方法、主要结果及限定）；关键词、MSC；引言（已知理论、文献缺口、本文贡献与主定理）；定义、符号、预备结果；核心定理及按逻辑拆分的证明；应用、反例、计算证书及局限；结论/开放问题；文献、数据和 AI 使用声明（按实际与期刊要求）；必要附录。把可复现的长枚举表、辅助计算和程序放附录/补充材料，但正文须有完备性论证。不要把每一轮对话拼成章节。

## 语言与可核查性

- 写给初次接触论文的专业读者。每节先说明要解决的问题，随后定义对象及引入新符号的必要性，最后解释结论及与下一节的关系。不要突然引入状态集、生成函数、差分算子或复杂下标。
- 给出适量真正有帮助的例子；数值例子应与公式一致，图示必须标明含义，不能替代证明。复杂等式分行排版，统一符号与定理编号。
- 用明确的量词、条件、结论，避免“显然”掩盖关键步骤。涉及代码的证明须交代程序究竟检验什么、如何判定、为何足够；不声称计算结果是人类独立验证。
- 摘要及结论中区分已知理论、本文推论、真正新增结果；对未确认原创性的主张用克制措辞。准确引用，不捏造 DOI、卷期、页码。中文稿避免不必要中英混排；专名、符号和通用术语保留规范形式。
- LaTeX 工具可用时实际编译至少至交叉引用稳定；检查日志中的 undefined references/citations、overfull boxes、缺字；渲染页面，检查长公式、脚注、表格、标题、图与空白。必要时迭代。不要声称未执行的 QA 已完成。

## 模拟匿名审稿流程

单独审稿也按 `quality-gates.md` 的证明、计算、文献、稿件四项要求给出覆盖范围和实际发现。对缺材料而无法核查的项目，指出缺什么及对结论的影响。正式定稿另做验收复核，使用实际修订版、当前证据及全部问题记录。

1. 确认稿件版本、可读附件和实际读取范围；首先概括文章的核心问题和贡献，不将作者自述视为已证。
2. 按主张台账追踪关键证明链；从量词、反例、外部定理适用性、计算完备性和下游推论做对抗性检查。审稿不是为提高分数而寻找赞扬。
3. 复核最接近的前人成果与引用，明确哪些贡献仅为已知定理应用。未完成全面检索时，不断言首创。
4. 有执行环境时运行所附代码；对核心例子尽量独立实现。准确区分重跑、代码审查、独立复现、未运行。检查版本和实际日志。
5. 出具审稿决定（拒稿/大修/小修/可接受），说明原因；按严重性排序，每条意见写位置、问题、影响和可核验的修改要求。对无法核实的结果直接说无法核实，不伪造章节编号或行号。若发现致命数学错误，优先指出而非用排版建议淡化。
6. 如用户询问期刊水平，查当前官方 scope、期刊分区口径和最近相关论文；不混淆 JCR 与中科院分区。稿件潜力是条件性判断，不是录用保证或真实评审评分。

## 大修执行

在本轮执行“意见 → 核查 → 实际修改 → 重验 → 逐条回复”。有数学漏洞先修数学，再重写摘要、引言、主定理及所有依赖，最后统一排版。重跑受影响的计算，保留旧稿备查。只做文字改写不能算完成需要新证明的意见。证据支持缩小主张范围、标成猜想或撤回时，实际改稿并重核所有受影响的主张；证据只支持部分修复时，保留未结项并记录这轮已做的工作。回复须引用实际修改和验收文件。只有 PDF 时使用可粘贴的替换段落或证明补丁。

## 交付检查

| 交付物 | 应包含 |
|---|---|
| 论文 PDF | 实际编译并渲染检查的版本 |
| LaTeX 源码 | tex、bib、图表和依赖，编译说明 |
| 复现材料 | 算法说明、源码、输入、执行命令、真实日志及计算证书 |
| 研究台账 | 当前主张、证明状态、文献依赖及原创性判断 |
| 审稿回复 | 逐条改动位置和未完成项 |
| 交接说明 | 当前成果、环境、待解决任务、下一步建议 |

发布前核实作者署名、单位、联系方式、利益冲突、AI 使用说明和期刊政策；不自行填造或代作者确认。对未发表研究默认不公开。只在用户明确要求且权限支持时上传或投稿。输出链接前检查文件实际存在。
